This part already runs.

No app to wait for. From the command line, ACP finds your agents, gives them the project's memory and keeps their work off your branch.

  1. It finds the agents you are signed in to

    You sign in to each agent in its own app. ACP starts them and never sees your password or tokens.

  2. It knows a design task when it reads one

    Front-end work gets the built-in design skills attached. Nobody has to call a skill by name.

  3. It runs the agent in its own worktree, then stops

    You get a branch and a list of changed files. The decision to merge stays with you.

Terminal · three real commands

Four steps from a goal to a change you approved. Each one says how far along it is.

  1. Connect what you have

    Claude Code, Codex, and free or local models through OpenCode. Antigravity is planned.

    Works from the command line

  2. Pick an orchestrator

    Star one or two agents. They split your goal into tasks and hand each to the agent best suited to it.

    Being built

  3. Work runs in parallel

    Each task runs in its own Git worktree. If an agent stops, another picks up from the latest checkpoint.

    Worktrees work, hand-offs being built

  4. You approve every change

    Each patch is checked, then waits. Tool results are evidence. AI comments are marked as opinion.

    Works in the local dashboard

A new agent.
Not a fresh start.

The plan, the decisions, the mistake you already fixed: the next agent should know them too. ACP keeps that memory as plain files in your repository, in layers.

Each task gets what applies to it, not the whole repository and not the whole chat.

  • You

    Preferences that follow you to every project.

    ACP's own storage

  • Project

    Goals, rules and decisions, kept in Git.

    .acp/knowledge.md

  • Folder rules

    Guidance matched to the files a task touches.

    .acp/rules/*.md

  • Task

    Checkpoints and a compact hand-off note.

    .acp/local/

Broad at the top, specific at the bottom.The narrower layer wins.

A guard against repeated mistakes

When a fix is approved as a rule, ACP shows it to the next agent that works on the same files, before it starts.

Memory any agent can reach

ACP runs an MCP server, so any agent that speaks MCP can read the memory and leave a checkpoint. It also writes a short summary into the AGENTS.md and CLAUDE.md files your agents already read, without touching your own text in them.

Evidence before opinion

Every change passes the same checks, whichever model wrote it. A test result is evidence. A model's comment is labelled as a judgment, so you can tell them apart.
