Memory

How much memory an agent receives and how the summary files stay current. The memory itself is in Memory.

Matching rules are added whole, most specific first, until this is full. A rule is never cut; one that does not fit is named so the agent can open it.

The knowledge and one line per rule. Over this, sync stops and tells you what to shorten.

Largest checkpoint

Fixed at 4 KB. A checkpoint is a short note of what is done and what is next, not a transcript.

4 KB

Off: ACP tells you the file is out of date and you run acp /memory sync. On: ACP rewrites its own marked block, never your text, and leaves the commit to you.

Reads what your agents remember and turns it into proposals. Nothing is imported until you accept it, and the original files are never changed.

5 proposals

The rule is not removed. You get a proposal to accept or reject.

Connections

ACP has one MCP server of its own. It gives an agent this project's memory and checkpoints. Agents that ACP starts get it without setup; add it once to an agent you start yourself.

ACP's MCP server

Runs only while an agent uses it, on this computer, for the folder the agent was started in

Ready

Add it to Claude Code

claude mcp add acp -- acp /mcp

Add it to Codex

codex mcp add acp -- acp /mcp

Run the command in your project folder. OpenCode reads MCP servers from its own config file; that setup has not been tried yet.

What an agent can do through ACP's server

Privacy & data

ACP runs on this computer and has no server of its own to send your work to. What leaves the computer is what each agent sends to its own provider.

Stays on this computer

  • Your project, its worktrees and every diff

    In the project folder and worktrees/

  • Memory

    .acp/knowledge.md and .acp/rules/ in the repository; your own preferences in the data folder

  • Checkpoints, handoff.md and proposals

    .acp/local/, which Git ignores

  • Credentials you gave a task

    Encrypted in the data folder; removed when the task ends; never in chat, memory, checkpoints or logs

  • Settings and logs

    The data folder. Logs are scanned and secrets removed before they are written

Advanced

Limits that keep a run from going on for ever, and where runs live.

A run that changes nothing. Stopped at a checkpoint when the time is up.

A run that may edit files in its worktree.

A command that runs longer is reported as failed, with the time it ran.

Each has its own worktree. More tasks use more of this computer and of each plan.

Where each run's copy of the project is created. Inside the project and ignored by Git, or any folder on the same disk.

The same as acp /runs clean. A run that holds work is never removed without your confirmation.
