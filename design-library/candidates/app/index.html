AACP

Every page and state

Thirteen pages, one stylesheet, one small script. Each link opens a page in that state; the dashed bar at the top of a page moves between its states. Every page also has a narrow layout: make the window 390 wide, and switch theme from the sidebar.

Connect agents, pick a project, find or set up memory.

  • 1 · AgentsReady, signed out with the command to run, planned
  • CheckingLoading: asking each tool for its state

  • 2 · ProjectRecent Git folders, a very long path, or type one
  • Not a Git folderError: the folder is refused, with the reason and the fix

Work

Thread

The home. One kind of thread: a question gets an answer, a change request becomes tasks.

  • Tasks workingFour tasks in parallel, each with its agent, branch and checkpoints
  • EmptyA new thread, before the first request
  • Just sentA request shows as working the moment it is sent
  • Task openedCheckpoint timeline, handoff.md, Stop this task
  • Ready to reviewReview is a button on each ready row
  • StoppedResume on the stopped row
  • Hand-offOne agent reaches its limit and another continues
  • Question answeredAn answer inline, with no tasks
  • Secret requestThe private card: given, declined, removed
  • LoadingReading the thread
  • Sign-in refusedError: an agent must be signed in again in its own tool
  • Long contentLong titles, paths and many tasks
  • Message boxAgent or orchestrators, permission mode, and the Commands menu for /run, /memory, /runs clean

Review

Nothing reaches the project until it is approved here, one change at a time.

  • QueueChanges waiting, with size and check results

  • Design-check findingsFindings as evidence, with file and line
  • Failed checkError: approve is held back, with the failing output
  • AppliedWhat was applied and where
  • EmptyNothing waiting
  • LoadingRunning checks
